# Extreme Programming (XP) Summary

## 1. What is XP?

Extreme Programming (XP) is an Agile software development method that focuses on short development cycles, frequent feedback, teamwork, testing, and adapting to changing requirements.

The main XP values are:
- Communication
- Simplicity
- Feedback
- Courage
- Respect


## 2. User Stories

User Stories describe what the customer wants the system to do.

A common format is:

> As a [user], I want [feature], so that [reason].

For example:

> As a student, I want to log in so that I can access my dashboard.

User Stories focus on user needs rather than technical implementation.


## 3. Engineering Tasks

Engineering Tasks are the technical tasks required to implement a User Story.

For example, for a login User Story, Engineering Tasks may include:

- Create the login page
- Implement authentication
- Connect to the database
- Write login tests

In our project, these tasks can be tracked using GitHub Issues.


## 4. Key XP Practices

Some important XP practices are:

- **Small Releases** – develop and deliver working software in small steps.
- **Simple Design** – use the simplest solution that meets current requirements.
- **Testing** – test features continuously during development.
- **Refactoring** – improve code structure without changing its behaviour.
- **Pair Programming** – two programmers work together on the same task.
- **Continuous Integration** – regularly combine and test everyone's code.
- **Collective Ownership** – the whole team shares responsibility for the codebase.


## 5. XP Roles in COMP3888

### Customer
Explains project requirements, gives feedback, and decides priorities.

### Programmer
Implements User Stories, writes code, tests features, and fixes problems.

### Manager
Coordinates team activities, meetings, deadlines, and communication.

### Tracker
Tracks project progress and checks whether tasks are being completed as planned.

### Coach
Helps the team understand and follow XP practices.

### Doomsayer
Identifies possible risks and problems before they become serious.

### Integration Tester
Checks whether different parts of the system work correctly together.

### Usability Tester
Checks whether the system is easy and clear for users.

### Report Writer
Helps organise and prepare project reports.

### Demo and Poster
Helps prepare project demonstrations, presentations, and posters.

### GitHub Expert
Supports the team with GitHub, branches, pull requests, and issue tracking.

### XP Expert
Researches XP and helps the team apply XP practices correctly.

### Software Researcher
Researches useful tools, frameworks, APIs, and technologies.

### Existing Systems Researcher
Researches similar existing systems and identifies useful ideas or features.


## 6. Role Rotation

Some roles, especially **Manager** and **Tracker**, will rotate during the project.

This allows different team members to practise leadership, planning, communication, and project management skills.


## 7. How We Will Use XP

Our team will:

1. Communicate with the client.
2. Create and prioritise User Stories.
3. Break User Stories into Engineering Tasks.
4. Track tasks using GitHub.
5. Develop features in small iterations.
6. Test and integrate code regularly.
7. Demo working features to the client.
8. Use feedback to improve the next iteration.


## 8. Key Takeaways

The main idea of XP is to develop software step by step instead of trying to finish everything at once.

XP also emphasises:

- regular client communication,
- teamwork,
- continuous testing,
- simple design,
- frequent feedback,
- and adapting to change.
